What / why

Codex Titanium, CLI-first

Titanium Host (also referred to as Titanium CLI on this surface) is the public install and onboarding hub for codex-titanium: an independent source fork of OpenAI Codex CLI. Monorepo tip documents 0.147.0-alpha.11-titanium.1 (family titanium.1). Homebrew formula and latest public GitHub Release ship the published formula artifact and may lag (e.g. a 0.146.*+titanium.1 pin). Always verify with codex-titanium --version on the box you installed — do not treat monorepo tip as the brew deliverable.

  • Binary lives in github.com/VeigaPunk/codex-titanium — this site does not vendor the Rust monorepo.
  • Primary install: brew install VeigaPunk/tap/codex-titanium (Linux x86_64; formula pin may lag monorepo).
  • Secondary: Cargo build from codex-rs until other platform artifacts ship (use for monorepo HEAD / non-x86_64 Linux).
  • Disambiguation: not Grok Builder (ds4cc marketplace), not grok-build-config-builder / Config Builder, not stock Homebrew cask codex / npm @openai/codex.

Titanium is tuned for multi-agent v2 at 64 threads, DS4CC marketplace plugin defaults, and hard-disabled MCP, host apps, memories, and built-in browser-use lanes. Runtime policy is configurable — see risk ladder.

Install

Get codex-titanium on PATH

Prefer the verified Homebrew formula. The formula installs both codex-titanium and a codex symlink from a SHA-256-pinned release artifact. Formula version can lag monorepo HEAD — confirm with --version.

Primary — Linux x86_64
brew install VeigaPunk/tap/codex-titanium
codex-titanium --version

Homebrew (primary)

brew install VeigaPunk/tap/codex-titanium — SHA-256-verified Titanium release artifact from VeigaPunk/tap (Linux x86_64 only today).

Cargo (secondary)

Clone codex-titanium, build the Rust CLI from codex-rs with Cargo. Use when brew artifacts for your platform are not published yet, or when you need monorepo HEAD instead of the formula pin.

Optional — apply Titanium preset (run from codex-titanium monorepo root after clone)
install -Dm600 titanium/config.toml "${CODEX_HOME:-$HOME/.codex}/config.toml"

Config · risk ladder

Runtime policy (not a hero feature)

Defaults ship unrestricted for Godspeed and L3 operators who already accept full host control. That is a conscious risk choice, not a marketing brag. If you need sandboxed execution or approval prompts, edit config before routine use. Deep field editing lives in the Config Builder sibling.

Default rung (Godspeed / L3)

approval_policy = "never"
sandbox_mode = "danger-full-access"

Unrestricted local agent. Suitable only when the operator trusts the model + workspace.

Tighter rungs (edit config)

approval_policy = "on-request" | "untrusted"
sandbox_mode = "workspace-write" | "read-only"

Prefer these for shared machines, untrusted repos, or compliance-bound hosts.

Risk ladder — pick your rung before copying the preset

  • Rung 0 · Read-only approval_policy = "untrusted" · sandbox_mode = "read-only" Audit and evaluate the fork. No writes, no surprises.
  • Rung 1 · Workspace write approval_policy = "on-request" · sandbox_mode = "workspace-write" Daily driver: edits stay in the repo, approvals on escalation.
  • Rung 2 · Godspeed preset approval_policy = "never" · sandbox_mode = "danger-full-access" Isolated hosts / VMs only. Full filesystem + network, zero prompts — you own the blast radius.

Source of truth: titanium/config.toml in codex-titanium. Interactive TOML UI: grok-build-config-builder (Config Builder).

Policy

No MCP zoo · no built-in browser lanes

Titanium removes mcp / mcp-server command implementations and hard-disables host-owned apps and every configured MCP server at runtime. Agent memories, external memory import, and Chronicle are off. Built-in browser-use, web-search, in-app-browser, and computer-use lanes are disabled.

Authenticated web UI adapters (when you need them) use agent-browser on loopback CDP :9222 — Puppeteer / Musketeer / Almanacker / kimiraikkoner — not an MCP middleman zoo. Exa research stance and marketplace docs live on ds4cc; this hub stays CLI install + posture.

Verify

Post-install gates

Confirm binary identity and that Titanium is first on PATH before sekhmet fan-out.

  • codex-titanium --version Expect a titanium family string (titanium.1 channel). Monorepo tip and brew formula can differ — trust this output, not a single site pin.
  • which codex-titanium; which codex; type -a codex PATH order matters — Titanium symlink vs stock OpenAI codex.
  • export CODEX_BIN=codex-titanium Point sekhmet / xbrd-spark workers at this host binary.
  • sekhmet swarm -j 64 -f tasks.md L3 plane after Titanium is on PATH (operator stack).
